# SQLite

在 Enso 里只读浏览和查询 SQLite 数据库（`.db`、`.sqlite`、`.sqlite3`）。可以按列排序和筛选，运行 SQL，并查看表、视图、索引、触发器的 `CREATE` 语句。

界面是中文。需要 Enso 0.3.4 或更新版本。

## 打开

- 文件查看器：清单把这三种后缀注册成默认打开方式。宿主若把文件交给查看器，会直接进入对应数据库。
- 侧栏「SQLite」：输入项目内相对路径，或点「查找」。当前 Enso 的文件面板遇到含空字节的文件会拒绝打开，真正的 SQLite 文件通常进不了文件标签，这时用侧栏。

重新读取会再从磁盘装入一次。翻页和筛选使用已经装入内存的副本。

## 数据、查询、结构

- **数据：** 左侧选择表或视图。点列名在升序、降序和不排序之间切换。列名下的输入框可筛选：直接输入表示包含；也可用 `=x`、`!=x`、`>x`、`>=x`、`<x`、`<=x`、`null`、`!null`。上方「搜索行」匹配任意列。
- **SQL 查询：** ⌘/Ctrl + Enter 运行。若文本框里有选区，只运行选区。多条语句按顺序执行，表格显示最后一条有结果的语句。点「取消」会停掉正在跑的查询。
- **结构：** 列出表、视图、索引、触发器和它们的 `CREATE` 语句。
- 点单元格可在下方看完整内容。拖选或按住 Shift 选择范围，⌘/Ctrl + C 复制成制表符分隔文本，右键可以带上列名。
- **导出 CSV** 复制到剪贴板，并尝试触发下载。单次最多约 512KB；沙箱页面未必能弹出系统保存对话框。

每页 50、100 或 200 行。查询在插件进程的工作线程里执行，避免卡住界面。

## 为什么只读

Enso 的 `fs.readText` / `fs.writeText` 和文件查看器的 `enso.file.text` / `update` 都是 UTF-8 文本。SQLite 文件含有空字节和任意字节，按文本读写会损坏文件；查看器的 `update` 还会把整个编辑缓冲区交回去保存，冲掉数据库自己的 `-wal` / `-journal`。因此本插件不调用 `writeText`，也不调用 `enso.file.update`。

读取时，若文件不超过宿主文本接口的 5MB，并且 `fs.readText` 能无损还原出 SQLite 文件头，就使用这份文本。否则按文件查看器或侧栏给出的项目相对路径，用插件进程读取原始字节。路径必须留在项目目录内，符号链接不能指向项目外面。字节装入内存中的 [sql.js](https://github.com/sql-js/sql.js)（SQLite 的 WebAssembly 构建），并立刻执行 `PRAGMA query_only = ON`。`INSERT`、`UPDATE`、`DELETE`、`CREATE` 会被拒绝；也不能 `ATTACH`、加载扩展或关掉只读。

不会把修改写回磁盘。要改数据，用 `sqlite3` 命令行或应用自己的写入路径。

## 其他限制

- 最大 64MB。sql.js 要把整库放进内存。
- 若旁边有非空的 `-wal` 或 `-journal`，界面会提示：那些还没合并进主文件的写入不会出现在结果里。
- 打不开 SQLCipher 等加密库。
- 一次最多 100 条语句，SQL 文本最多 10 万字符。列名重复且带了筛选时，最多在内存里处理 1 万行。

## 权限

| 权限 | 用途 |
| --- | --- |
| `ui.view` | 侧栏页面和文件查看器 |
| `fs.read` | 在文本接口能够无损还原时，读取整个项目里的数据库文件 |

原始字节读取发生在插件进程内，范围同样限制在当前项目目录，并且只接受上述三种后缀。
