# 模型指纹

在侧栏里看当前会话的模型最像参考库里的哪个模型。检测用 [Fingerpoint Detector](https://lm.ikale.io)（`lmfpd-sdk`）：出 3 道随机整数题，交给当前会话的模型作答，再在本机离线评分。

## 用法

1. 打开右侧栏的「模型指纹」，点「开始检测」。只有点按钮才会检测。
2. 面板依次显示：加载参考数据、3 道题各自的状态和实时数字计数、评分。可以随时取消，取消的这一轮不评分。
3. 出结果后显示：
   - 最像的模型、所属家族和置信度。没有置信度时写明原因，比如只有两条有效回答。
   - 候选排名，前 6 名带分数条，可以展开到前 12 名。
   - 每道题解析出多少个数、最少要多少个、是否有效，以及题目和原始回答。
   - 数字的变化方式像不像语言模型写的。
   - `agent.run` 返回的实际模型名，和预测对照。
4. 每个会话保留最近 5 次结果，可以点开回看。

**每次检测会花 3 次模型调用。** 结果是参考库内的相似度排序，不是身份证明：库外的模型也会得到一个「最像」的候选，置信度只在库内模型之间比较。

## 它做了什么

- 题目由 `generateChallenges(3)` 生成，每道随机用中、英、日、韩、法文之一，要求 292–332 个 1–355 之间的整数。
- 每道题用 `enso.agent.run` 交给当前会话的模型：不带对话（`context: 'none'`），不另加系统提示。插件同时最多跑 2 个，第三道排队。
- 回答收齐后用 `detector.analyze` 评分。有效回答至少要有 `max(80, ceil(要求个数 × 0.55))` 个整数；超出要求的部分按宽松模式截掉。
- Enso 的只读代理带有 Enso 自己的系统提示和只读工具，模型偶尔会先调用工具或多写几句话，结果可能和直接调用接口时不同。面板会显示每道题调用了几次工具。

## 参考数据

参考数据不随插件分发。第一次检测时经 `enso.net.fetch` 从 `lm.ikale.io/data/` 下载 `bundle.json` 和约 4.4MB 的 zstd 分块（失败时改用镜像 `cdn.jsdmirror.com/npm/lmfpd-data@latest/`），解压并按 `sha256` 校验后存进插件自己的数据目录，再以本地目录交给 SDK。之后每 24 小时在后台检查一次更新，下一次检测才用上新数据。卸载插件时数据一起删除。
