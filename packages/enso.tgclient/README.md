# Telegram 客户端

在 EnsoCode 侧栏里登录自己的 Telegram 账号（MTProto，基于 [GramJS](https://github.com/gram-js/gramjs)），像官方客户端一样聊天。

需要 EnsoCode 0.3.14 及以上。

## 使用

1. 打开侧栏「Telegram」，填入带区号的手机号，获取验证码登录；开了两步验证的再输入云密码。
2. 国内网络在 设置 → 插件 → Telegram 客户端 填写代理：`socks5://127.0.0.1:7890` 或 MTProxy 链接。

登录信息只保存在插件数据目录（`account.json`），卸载插件即删除。插件常驻运行，侧栏关着也能收到新消息通知。

## 功能

- 会话列表：置顶、未读数、@ 提醒、静音、在线状态、搜索
- 聊天分组：同步手机端建好的分组（文件夹），顶部标签切换，带未读数，另有「已归档」
- 会话列表滚动到底部自动加载更多
- 右键消息：快捷表情回应、回复、复制、编辑、删除；自己发的消息可看谁已读及已读时间（私聊、100 人以内的群、7 天内）
- 视频边下边播（50MB 以内；少数索引在文件末尾的视频要下完才能播）
- 相册：收到的多图合成一组显示，大图里左右切换；选多张图片或视频发送时自动合成相册
- 话题（论坛群）：先显示话题列表（置顶、未读、已关闭），点进话题收发消息；聊天顶部有话题标签栏随时切换，「全部」把所有话题的消息合在一起看；各话题草稿分开
- 群里切换发言身份：以个人或自己管理的频道身份发言
- 聊天：实时收发、回复、编辑（↑ 键编辑上一条）、删除自己的消息、表情回应、富文本、链接预览、已读回执、上滑加载历史
- 表情与贴纸面板：常用表情、已安装贴纸包、最近与收藏的贴纸
- 机器人：内联按钮（回调、链接、切换内联、复制）、回复键盘、空聊天一键「开始」
- 媒体：图片、贴纸、动图、语音、视频（≤50MB 侧栏内播放）、文件下载到「下载」文件夹
- 发送图片和文件（≤20MB），支持粘贴图片
- Agent 工具：`tg_current_chat` 获取侧栏当前打开的对话和最近消息、`tg_list_chats` 列出聊天、`tg_search_chats` 搜索聊天/联系人/公开群和频道、`tg_list_topics` 列出论坛群的话题、`tg_get_messages` 查看聊天记录、`tg_search_messages` 搜索消息（单个聊天或全部）、`tg_send_message` 以本人身份发消息、`tg_send_media` 以本人身份发本地图片（单张或相册）、`tg_mark_read` 标为已读、`tg_wait_messages` 等新消息（长轮询，带 cursor 不漏消息）、`tg_watch` / `tg_unwatch` 订阅新消息（攒几秒投递到会话并自动开始新一轮；`keywords` 只投递含关键词或 @我、回复我的消息，`tg_wait_messages` 同样支持；`topic` 只订阅论坛群里的一个话题，id 来自 `tg_list_topics`，General 为 1，必须同时指定这一个聊天；多群订阅时改用 `chats: ["群A", { chat: "群B", topic: 55 }]` 把话题约束绑到单个群上，没写 topic 的群收该群全部话题；不填则该聊天的每个话题都投递；需在插件设置里打开「允许向任意运行中的会话发送消息」；侧栏顶部的眼睛图标列出所有订阅，可查看投递情况并取消）；聊天可用 id、@用户名或名称指定，不填则用侧栏当前打开的对话（论坛群里还会沿用当前话题），需先在侧栏登录
- 订阅只在 `tg_unwatch` 或取消订阅时结束：投递失败（会话没在跑、没开跨会话授权、限流）不会删除订阅，消息留在队列里按 5 秒 → 5 分钟指数退避重试，连续失败 5 次才弹一次系统通知，侧栏订阅列表里能看到最后的失败原因
- 投递细节：处理期间在该聊天显示「正在输入」（每 4 秒刷新，发出回复、会话回合结束或满 90 秒即停）；@我或回复我的消息跳过安静期立即投递，队列里攒着的普通消息并进同一批只投一次；自己发出去的消息同样会投递（手机上手打也算），只有本插件自己发出的消息会被跳过，避免回复把自己再唤醒一次；图片会随消息一起转达，最多 4 张，几张同时下载、共用 45 秒时限（盖过 GramJS 在文件所在 DC 连接卡住时 30 秒后的重连重发），超时的在正文标注「下载失败未转达」
- `tg_watch` 投递附带结构化 `sender`（`channel` 为 `telegram`，另有 `chatId`、`userId`、`displayName`），供宿主判断是不是 owner，以及外部投递的边界。防抖批里混有多个发送者时按发送者拆开投递。频道和匿名身份不填 `userId`
- 投递节奏可调：`debounceSec`（安静期，默认 3 秒，最长 1 小时，连发的几条合成一批）和 `minIntervalSec`（两次投递的最小间隔，默认 0 不限，最长 24 小时）——群消息很密集时把它设成 60 或 300，避免每几秒就唤醒一次 agent
- 处理状态表情：投递成功后给原消息点 ⚡，回合结束换成 ✅（失败 ❌；表情不被允许时退到 👍/👎）；宿主拒收（认领在别的会话）时不点表情、也不显示正在输入；同一聊天同时只挂一个 ⚡、两次请求至少隔 2 秒，失败静默忽略；`tg_watch` 传 `reactions: false` 关闭
- 0.7.0：宿主有认领接口时，多个会话监听同一群，一条消息只投给认领它的会话（键 `tg:<chatId>:<被回复的消息 id 或本条 id>`，回复归到原消息）；没有该接口的旧宿主仍投给每个监听。`tg_unwatch` 或替换监听时释放本会话的 `tg:` 认领
- `tg_track_demand` 把认定为需求的群消息登记成需求线程（发起人取自消息本身）。之后 PR 开出、CI 失败、合并、需要人这些里程碑由 EnsoCode 自动回复原消息。不要自己把 PR 评论或 CI 结果转发回群
- 0.8.0：`tg_send_media` 以本人身份发 1 到 10 张本地图片。参数 `chat`（规则同 `tg_send_message`）、`files`（绝对路径）、`caption`（挂在第一张或整个相册上）、`asAlbum`（默认 true，多张合成相册；false 逐张发）、`topic`、`replyTo`；返回每条消息的 `ids`，相册一张图一个 id。相册里有 gif 或 webp 时整组按文件发（Telegram 的规则）

## `tg_send_media` 能读哪些文件

先 `realpath`，再要求落在下面这些目录里，符号链接指到外面一律拒绝：

- 系统临时目录：`/tmp`、`/private/tmp`、`os.tmpdir()`、`/var/folders`
- 调用会话的项目目录（会话在 worktree 里就是那个 worktree），以及 EnsoCode 数据目录下的 `worktrees/`
- EnsoCode 的聊天图片目录：数据目录下的 `bot-chats/`，以及环境变量 `ENSO_USER_IMAGE_DIRS` 里的目录

只收图片：按文件头认 png、jpg、webp、gif，不看扩展名；单个文件最大 10MB。不支持任意文件。路径、大小或类型不对时直接报错，什么都不上传。

这些目录不在「当前项目」之内的部分由插件进程自己读取，不走宿主的 `fs.read`，所以清单的权限没有变化。

## 开发

`vendor/gramjs.mjs` 是打包产物，不要手改。更新 GramJS：

```bash
cd scripts/tgclient && npm ci && node build.mjs
```
